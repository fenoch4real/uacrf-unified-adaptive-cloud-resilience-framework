# Cloud provider and graph visual refinement

Version 1.0 · UI design revision 5 · Visual refinement 1 · October 30, 2026.

The provider marks now appear in the shared header across all 45 prototype views and the 13 current screen illustrations. Six graph views restore directed relationships, provider grouping, capability types, explicit evidence states and routes into the related review page. They cover service dependencies, recovery independence, changed decision context, model dependencies, protected agent dependencies and multi-agent roles with shared dependencies.

Provider names and node placements are sample context. They do not establish connected accounts, deployed resources, current access or independent recovery. Graph direction remains explicit; topology does not prove causation. Missing evidence and mandatory-role gaps remain visible. The graph sources are editable SVG, with provider marks embedded locally for offline use. Browser interaction and accessibility review remain pending, as documented for design revision 5.

The established architecture, database, API and formal requirements are unchanged. The nine existing technical/disclosure Word/PDF pairs and the interface reading guide remain the same baseline. This note is their visual implementation addendum. The full package keeps all documents together in DOCUMENT_LIBRARY.html.


## Services only entry point

Visual refinement 2 makes Service dependencies a permanent main-navigation entry. UI-18 shows Checkout service and its API, data and identity dependencies, with service-specific health, evidence and recovery review. Agent dependencies remain separately available in UI-37. Sample data and all existing authority limits remain in effect.


## Graph workspace layout refinement

Visual refinement 3 restores the journey-oriented graph layout. A large dependency canvas sits beside runtime health, evidence qualification, recovery state and a selected-relationship inspector. Inline provider marks identify sample GCP, AWS and Azure placement; neutral resource icons distinguish services, APIs, data stores, identities, agents and journey steps. These resource glyphs describe types and are not vendor-specific product logos.

The six graph workspaces use this layout, with Service dependencies remaining directly available in the main navigation. Select a node with a pointer or keyboard to inspect its relationship context locally. Sample observations do not establish live provider connectivity or safe recovery. Browser interaction, responsive layout and accessibility acceptance remain pending; source fixture and static rendering checks are separate.
