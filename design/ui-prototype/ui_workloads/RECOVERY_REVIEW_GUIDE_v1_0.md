# Recovery independence and changed decision context

Version 1.0 · Recovery-review refinement 7 · Maintained in UI design revision 8 · Alignment revision 22

Both review workspaces now offer Service and Agent examples through the Workload example selector. The choice controls the graph, scenario checks, next-review destination and scoped recent activity for these screens. The journey filter remains separate and does not re-query a graph. Arrival from a dedicated agent or service graph selects the matching example; direct entry defaults to Services. Switching between the two review workspaces retains the choice.

Recovery independence asks whether a proposed alternate path can survive the stated failure. Service review checks deployment, capacity, identity and data failure domains. Agent review also checks model compatibility, tool access, knowledge, memory and runtime identity. Different regions, providers or model names do not establish independence. Current conclusions remain Unknown until qualified evidence supports them.

Changed decision context compares a retained decision with a hypothetical later change. The service example concerns a deployment and dependency-access delta. The agent example concerns a tool grant or schema change after a checkpoint was created. These are comparisons, not claims that the fixed inventory snapshot or current grants actually changed. Existing authority must be reevaluated against the exact workload, graph, policy and objective revisions. A checkpoint or old evaluation does not authorize changed context or expanded effects.

The existing dependency canvases and provider marks remain. New summary diagrams show review sequence, not additional runtime dependency edges. The relation inspector remains an illustrative explanation, not a live source query. Live recovery dispatch is unavailable. Canonical APIs, SQL, graph vocabulary, applied migrations, formal requirements, patent claims and objective-extension status are unchanged. The architecture already supports governed service and agent recovery; this correction fills an example coverage gap rather than adding recovery authority.

## Visual refinement 7

The two reviews use a workload selector, labelled Unknown/authority status panels, an icon-led review sequence, four evidence-check cards and a prominent next-review action. Services, agents, alternate paths, retained context, changed context, identity and evidence reuse the shared vector icon set. Provider marks identify only explicit sample placement. Scope and live-action limits remain available in an expandable note. The detailed dependency canvas stays below the review summary. Narrow layouts stack cards and actions; keyboard focus styling remains shared. No new status, permission or recovery capability is introduced.
